# ТЗ: Интеграция Битрикс24 с приложением «Нетдолгофф — Партнёрская программа»

**Дата:** 03.04.2026  
**Приложение:** Реферальная программа для водителей такси  
**Версия:** 1.0

---

## 1. Цель интеграции

Обеспечить автоматическую передачу данных из партнёрского приложения водителей в Битрикс24:
- Все новые лиды (потенциальные клиенты) сразу появляются в CRM
- Статус лида обновляется автоматически при изменении в приложении
- Менеджеры видят, от какого водителя пришёл клиент
- Можно отслеживать конверсию и начислять бонусы водителям

---

## 2. Что происходит в приложении (логика)

### Как появляется клиент
1. Водитель показывает пассажиру QR-код или называет промокод
2. Пассажир переходит по ссылке / сканирует QR и попадает на сайт Нетдолгофф
3. Он оставляет заявку — в приложении у водителя появляется новый **лид**
4. После консультации юрист меняет статус лида в Битрикс24
5. Приложение водителя получает обновлённый статус → начисляет бонус

### Статусы лида
| Статус в приложении | Описание |
|---|---|
| `thinking` | Думает, не принял решение |
| `signed` | Договор подписан → водитель получает бонус |
| `declined` | Отказался |
| `no_match` | Не подошёл под банкротство (долг < 300 000 ₽) |

## 3. Что нужно настроить в Битрикс24

### 3.1. Пользовательские поля в Лидах / Контактах

Добавить в карточку **Лида** следующие поля:

| Поле | Тип | Описание |
|---|---|---|
| `UF_DRIVER_ID` | Число | ID водителя в приложении |
| `UF_DRIVER_PHONE` | Телефон | Номер телефона водителя |
| `UF_DRIVER_NAME` | Строка | Имя водителя |
| `UF_PROMO_CODE` | Строка | Промокод водителя (напр. `TAXI-AP2847`) |
| `UF_SOURCE_TYPE` | Список | Откуда пришёл клиент: `qr` / `promo` / `link` |
| `UF_DEBT_AMOUNT` | Число | Сумма долга клиента (в рублях) |
| `UF_APP_LEAD_ID` | Число | ID лида в базе данных приложения |

### 3.2. Настройка стадий лида

В Битрикс24 в разделе **CRM → Настройки → Стадии лидов** создать следующие стадии:

| Стадия Битрикс | Соответствует статусу в приложении |
|---|---|
| Новый | (начальная) |
| Думает | `thinking` |
| Договор подписан | `signed` |
| Отказался | `declined` |
| Не подходит | `no_match` |

> **Важно:** Названия стадий должны быть именно такими — по ним приложение определяет статус и начисляет бонус водителю.

### 3.3. Входящий вебхук (приём данных из приложения → в Битрикс24)

1. В Битрикс24 перейти: **Приложения → Вебхуки → Добавить вебхук → Входящий вебхук**
2. Дать права: `crm` (чтение + запись)
3. Скопировать URL вебхука
4. Передать URL разработчику приложения

**Что будет приходить через этот вебхук:**

```
При создании нового лида:
POST /crm.lead.add
{
  "TITLE": "Клиент от водителя Станислав | TAXI-AP2847",
  "NAME": "Имя пассажира",
  "PHONE": [{"VALUE": "+79991234567", "VALUE_TYPE": "WORK"}],
  "SOURCE_ID": "WEB",
  "UF_CRM_DRIVER_ID": 123,
  "UF_CRM_DRIVER_PHONE": "+79001234567",
  "UF_CRM_DRIVER_NAME": "Станислав",
  "UF_CRM_PROMO_CODE": "TAXI-AP2847",
  "UF_CRM_SOURCE_TYPE": "qr",
  "UF_CRM_DEBT_AMOUNT": 450000,
  "UF_CRM_APP_LEAD_ID": 456
}
```

### 3.4. Исходящий вебхук (из Битрикс24 → в приложение при смене статуса)

1. В Битрикс24 перейти: **Приложения → Вебхуки → Добавить вебхук → Исходящий вебхук**
2. Выбрать событие: **OnCrmLeadUpdate** (обновление лида)
3. В поле URL указать адрес эндпоинта приложения (предоставит разработчик)

**Формат данных, который будет отправляться автоматически:**
```
POST {URL_приложения}/bitrix-webhook
{
  "event": "ONCRMLEAD_UPDATE",
  "data": {
    "FIELDS": {
      "ID": "12345",          ← ID лида в Битрикс
      "STATUS_ID": "IN_PROCESS"  ← новый статус
    }
  }
}
```

> Разработчик приложения настроит маппинг статусов Битрикс → статусы приложения.

### 3.5. Настройка автоматизации (Роботы / Триггеры)

В разделе **CRM → Лиды → Роботы и триггеры** настроить:

**При переходе лида в стадию "Договор подписан":**
- Запустить вебхук на URL приложения с данными лида
- Ответственный менеджер получает уведомление

**При переходе в "Отказался" / "Не подходит":**
- Также запустить вебхук — водитель увидит обновлённый статус

## 5. Условия начисления бонуса водителю

Бонус начисляется автоматически в приложении **только после** того, как в Битрикс24 лид переходит в стадию **«Договор подписан»**.

Условия для ежемесячного бонуса (+50 000 ₽):
- 3 и более лида со статусом «Договор подписан» за календарный месяц
- Долг каждого клиента не менее **300 000 ₽** (поле `UF_CRM_DEBT_AMOUNT`)

> Это поле важно заполнять корректно — от него зависит начисление бонуса.

## 6. Схема потока данных

```
Водитель показывает QR-код пассажиру
        ↓
Пассажир оставляет заявку на сайте
        ↓
Приложение → создаёт лид в своей БД
        ↓
Приложение → вызывает вебхук Битрикс24
        ↓
Лид появляется в CRM у менеджера
        ↓
Менеджер проводит консультацию, меняет статус в Битрикс24
        ↓
Битрикс24 → отправляет вебхук в приложение
        ↓
Приложение обновляет статус лида у водителя
        ↓
Если статус = "signed" → начисляется бонус водителю
```

## 7. Что подготовить технику для разработчика

После настройки Битрикс24 передать разработчику приложения:

1. **URL входящего вебхука** (для создания лидов из приложения)
2. **URL исходящего вебхука** уже настроен в Битрикс — нужно получить от разработчика приложения URL для получения событий
3. **Коды пользовательских полей** — автоматически генерируются Битриксом при создании (вид: `UF_CRM_XXXXXXXX`) — скопировать и передать

---

## 8. Проверка интеграции

После настройки выполнить тест:

1. Зайти в приложение под тестовым водителем
2. Поделиться ссылкой → перейти по ней и оставить тестовую заявку
3. Убедиться, что в Битрикс24 появился новый лид с заполненными полями водителя
4. Сменить статус лида в Битрикс24 → убедиться, что в приложении статус обновился
5. Если статус сменить на «Договор подписан» — в разделе «Финансы» приложения должен появиться начисленный бонус
